# Home & tracking redesign — controller rulings and deferred minors

Rulings made during subagent-driven execution of `docs/superpowers/plans/2026-10-01-home-tracking-redesign.md`, in ledger order. Each records what was decided, why, and the cost if wrong. Copied from the execution ledger before its scratch workspace was deleted.

## Rulings

1. Ruling R1: the sleep-session migration is `000026_sleep_sessions.sql`, schema 26 — main took 25 for refresh recovery — if wrong: the manifest and pins must shift again (cheap).
2. Ruling R2: the new client always sends timer v5 and sleep v2, so it cannot sync with a pre-26 server. The server deploys first, per spec rollout — if wrong: phones fall to "out of date" until the server is upgraded; no data loss, because the outbox holds mutations.
3. Ruling R3: keep `TimerIntent.edit`'s `components` non-optional. `detachFromSession` sends `components: timer.completedComponents` (empty for one-part timers) — if wrong: an edit could resend unchanged components (harmless).
4. Ruling R4: HomeView exposes a HomeFeature-local `HomeAction` enum (`bottle`, `diaper`, `more`, `history`), with an `onAction` closure; RootView maps it to `LogSheet`. No new HomeFeature→LoggingFeature dependency — if wrong: only wiring changes.
5. Ruling R5: the Home redesign keeps the merged sync status card (`home.syncStatus`) under the header, and its recovery actions stay reachable at accessibility sizes — if wrong: sign-in recovery would be lost from Home (high), hence kept.
6. Ruling R6: T15 adds the `LogSheet.bottleAmount(feedID:)` case and BottleSheet `.amount` mode. T16 adds the PendingQuickLog marker and the RootView presentation of it — if wrong: the Set-amount prompt is not reachable until T16 (fine mid-branch).
7. Ruling R7: T6 adds SchemaV8 and must keep `SchemaMigrationTests` green. If those tests require a V8 fixture, generate it the way the existing fixture manifest documents, or extend the test to assert V7→V8 with the existing V7 fixture — if wrong: the migration coverage gap is caught by the final review.
8. Ruling R8: all simulator work uses `id=<simulator-udid>`. The compact-screen check becomes Ukrainian at XXXL text, and the second caregiver is the E2E harness rather than a second simulator — if wrong: the compact-width layout is not proven on a 17e-size screen.
9. Ruling R9: Task 3 owns making TestSharedCorpusPostgresRoundTripsEveryCanonicalKindExactly/sleep.json pass (GetSleep sets PayloadVersion) — Task 1's implementer ran only non-DB tests; the gap surfaced in Task 2's DB run — if wrong: a red sync DB test persists until fixed (caught by make server-test in T3/T4).
10. Ruling R10: the Sleep-Session feature header is cumulative — the server treats a request as sleep-session-capable only when it also carries Feeding-Session: v1 (every real client sends all headers; no client has Sleep without Feeding). Documented in docs/protocol/v1.md and openapi. Plus scope feed boundary active_timers clause to timer_kind='feed'. — Scoping every generic v>=4 gate by timer kind would need kind lookups for stop/edit payloads that carry no kind; cumulative semantics is exact and cheap — if wrong: a hypothetical third-party client sending only Sleep-Session is treated as not sleep-capable (refused, never corrupted).
11. Ruling R11: localisation gate is "no new verify-localizations problems vs main baseline" (main already has 268 pre-existing gaps, verified at 19071bf; baseline saved as loc-baseline-main.txt) — fixing the Ask catalog is out of scope — if wrong: pre-existing gaps stay; the redesign adds none.
12. Ruling R3 (revised): detachFromSession sends `components: []` — the edit wire contract patches components by id, so [] means "no component change"; re-sending completedComponents could overwrite a concurrent caregiver edit — if wrong: a detach could fail to carry components it never needed to.
13. Ruling R12: a bottle stopped on a device that did not start it uses the baby's most recently logged bottle contents (not a hard-coded .formula) — contents stay out of the wire format to avoid another protocol version — if wrong: a cross-device bottle stop may record the wrong contents (editable in History).
14. Ruling R13: keep the full-history session projection (needed to resolve session first-part days; feeds already did this). Task 14 must rebuild the snapshot only on data change (store.revision), scenePhase, and at most once a minute while idle — never per second; the seconds tick comes from TimelineView over Dates — if wrong: Home does a full-history fetch per data change, measurable only on very long histories; bounding with a lookback is a contained later change.

Removes the actionID ambiguity; overrides the brief's "no expansion yet" — if wrong: one extra disclosure level on joined sleeps until the History redesign.
16. Ruling R15: spec says "Supplements becomes Meds in all UI" — the add-flow copy (Add supplement / Add your first supplement / Supplement name / Use saved supplements, and any other visible "supplement" string) is renamed to med vocabulary in this task's fix round — if wrong: copy churn only.
