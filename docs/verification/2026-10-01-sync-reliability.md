## Approved architecture direction

1. **Session reliability:** add capability-gated, device-bound recoverable refresh. Persist an unpredictable attempt ID before send; commit a protected recovery receipt with rotation; retry the same bound attempt to retrieve the same result. A different attempt or stolen/replayed parent token does not become a valid recovery. Preserve annual expiry, explicit logout, membership/device revocation and epoch changes. Retain unacknowledged receipts until resolved or the original deadline, acknowledge only after durable client install, and protect response material with authenticated encryption or exact frozen derivation inputs. Add a resumable Keychain/SQLite installation checkpoint and privacy-safe failure-phase diagnostics. Surface a persistent sign-in requirement where logging occurs, rather than only on the family settings screen.
2. **Fast propagation and capacity:** establish a write-to-other-client-apply timing harness; repair the measured live-channel failures and immediate foreground catch-up; keep polling as a fallback. Cache verified authority state by trusted head and avoid replaying/cloning unchanged global history, with immediate invalidation and corruption/rollback/recovery checks. Index live connections by family. Repeat the authenticated current-client matrix and measure full composition, request errors, p50/p95/p99, throughput and memory at bounded concurrency before making capacity claims. Preserve fail-closed behavior; no proposal to bypass readiness or security checks merely to achieve a target.
3. **Delivery gates:** lost replies on either side of server commit, interrupted credential install, app/widget/intent concurrency, repeated same attempt, conflicting attempt, server restart/key rotation, revocation/epoch change, annual deadline, receipt cleanup and old client/server compatibility. Foreground delivery target is proposed at p95 under one second on a healthy private connection, with failures displayed accurately. Background timing remains subject to iOS; fast catch-up on foreground return is required. Capacity numbers must be agreed and measured, not inferred from 32-family samples.

Alternatives: shortening polling or extending token expiry is smaller but leaves interruption-driven sign-in and increases request load; replacing the entire auth/sync stack is a much larger migration without evidence it is necessary. The proposed recovery plus measured optimizations addresses the reproduced gaps while retaining the existing family isolation and authority model.

This investigation records approved architecture direction, written specifications and implementation plans, with subagent-driven execution selected. Implementation proceeds task by task with independent review. Server deployment and local main/app integration remain separate decisions for this new architecture.
