# Compact sleep duration in the Dynamic Island

Research date: 2026-09-26. Scope: the sleep Live Activity's compact trailing region in `Apps/BabyTrackerWidgets/FeedActivityWidget.swift`.

## Current behavior

The compact trailing region uses `Text(context.state.startedAt, style: .timer)` inside a 52-point maximum-width frame. The same timer text is also used in the expanded Island and Lock Screen card. Apple's timer date style counts from the supplied date; it does not expose field-count or precision controls. An elapsed duration of 1 hour 36 minutes therefore gains a third numeric field (`1:36:00`) and may be clipped in the compact region. [Apple timer date style](https://developer.apple.com/documentation/swiftui/text/datestyle/timer), [Apple Live Activity presentations](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities).

## Relevant Apple APIs and constraints

- Since iOS 18, `Text(.durationOffset(to: startedAt), format: .units(allowed: [.hours, .minutes], width: .narrow, maximumUnitCount: 2, fractionalPart: .hide(rounded: .down)))` combines a system-updating elapsed-duration source with a localized narrow units style. Apple says `TimeDataSource` values update in Live Activities, and its narrow units style produces labels such as `3h`. A local Foundation formatting check returned `1h 36m` for 96 minutes and `59m` at 59:59. Explicit downward rounding matters: the default rounded 59:59 up to `1h`, one second early. The iOS 27 SDK confirms `Duration.UnitsFormatStyle` conforms to `DiscreteFormatStyle`, which the updating `Text` initializer accepts. [Apple time data source](https://developer.apple.com/documentation/swiftui/timedatasource), [Apple duration units format](https://developer.apple.com/documentation/swift/duration/unitsformatstyle), [Apple narrow unit width](https://developer.apple.com/documentation/swift/duration/unitsformatstyle/unitwidth-swift.struct/narrow), [Apple live-updating Text initializer](https://developer.apple.com/documentation/swiftui/text/init%28_%3Aformat%3A%29-8sfgg).
- The elapsed offset is positive after `startedAt`: Apple's analogous date-offset style explicitly says an input date later than its anchor yields a positive value and shows elapsed time since a start date without a minus sign. [Apple date-offset sign behavior](https://developer.apple.com/documentation/swiftui/systemformatstyle/dateoffset/init%28to%3Aallowedfields%3Amaxfieldcount%3Asign%3A%29), [Apple date-offset example](https://developer.apple.com/documentation/swiftui/systemformatstyle/dateoffset).
- Another iOS 18 system timer style offers `maxFieldCount: 2` and minute precision, but this does not guarantee narrow unit output: a local formatting check in the project investigation returned `1 hour, 36 minutes`, too wide for the compact region. Its interval is also bounded. [Apple count-up timer initializer](https://developer.apple.com/documentation/swiftui/systemformatstyle/timer/init%28countingupin%3Ashowshours%3Amaxfieldcount%3Amaxprecision%3A%29).
- `showsHours: false` causes minutes to accumulate past 60, so it does not by itself solve the width problem. The older `Text(timerInterval:countsDown:showsHours:)` has a `showsHours` option, but no field-count or precision control. [Apple count-up timer initializer](https://developer.apple.com/documentation/swiftui/systemformatstyle/timer/init%28countingupin%3Ashowshours%3Amaxfieldcount%3Amaxprecision%3A%29), [Apple interval timer initializer](https://developer.apple.com/documentation/swiftui/text/init%28timerinterval%3Apausetime%3Acountsdown%3Ashowshours%3A%29).
- `Text` with a `TimeDataSource` keeps supported time formats current as time progresses. `DiscreteFormatStyle` gives SwiftUI the boundaries at which the displayed string changes. This avoids app-driven ActivityKit updates for every elapsed minute. Live Activities do not use widget timelines; ActivityKit updates are for changed activity data. [Apple live-updating Text initializer](https://developer.apple.com/documentation/swiftui/text/init%28_%3Aformat%3A%29-8sfgg), [Apple discrete format style](https://developer.apple.com/documentation/foundation/discreteformatstyle), [Apple ActivityKit overview](https://developer.apple.com/documentation/activitykit).
- `TimelineView` itself is documented as a scheduled view redraw, but Apple does not document it as a Live Activity timer mechanism. Apple's `TimeDataSource` explicitly supports Live Activities, so it is the stronger choice. [Apple TimelineView](https://developer.apple.com/documentation/swiftui/timelineview), [Apple time data source](https://developer.apple.com/documentation/swiftui/timedatasource).
- Apple chooses compact, minimal, and expanded Dynamic Island presentations based on circumstances. The compact trailing view has very limited space, so the final width and truncation need a device or simulator check at 59:59, 1:00, 1:36, and longer durations, plus a larger text setting. Apple's size guidance is presentation dependent. [Apple Live Activity presentations](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities), [Apple Live Activities HIG](https://developer.apple.com/design/human-interface-guidelines/live-activities).

## Recommendation

Try the `TimeDataSource.durationOffset` plus narrow `Duration.UnitsFormatStyle` **only in the compact trailing sleep presentation**. It directly expresses `1h 36m` after one hour and `59m` before it while letting the system advance the text. Keep the current second-accurate timer in the expanded and Lock Screen presentations. This is a small view-only change; it does not require periodic app work. Confirm minute-boundary updates after backgrounding and exact fit on a Dynamic Island device before calling it finished. A developer report describes inconsistent Dynamic Island updates and unexpectedly wide layout with this format, so the API promise alone does not establish runtime reliability. [Apple Developer Forums report](https://developer.apple.com/forums/thread/757140). A one-time `Date()` calculation in the widget view would become stale.

The current project package targets iOS 26, so the iOS 18 timer-format availability is compatible. The installed iOS 27 SDK interface also declares this API as available from iOS 18. This is source/API evidence, not a rendered-layout verification.
