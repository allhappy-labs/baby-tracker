# Ask Tab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a question-first Ask tab for grounded handoffs, log questions, and Insights explanations with one persistent, private, device-only chat per baby.

**Architecture:** `AskFeature` owns read-only fact assembly, model interaction, chat state, and UI. App-private storage holds displayed turns outside the App Group and sync schema. Swift computes all dates and figures; the on-device model chooses a bounded query and words a structured answer, which the app validates and renders with source links.

**Tech Stack:** Swift 6, SwiftUI, SwiftData `BabyStore` reads, Foundation Models `SystemLanguageModel`, Foundation file storage, XCTest/XCUITest.

**Spec:** `docs/superpowers/specs/2026-09-28-ask-tab-design.md`

## Global Constraints

- iOS and macOS deployment floor is 26; use the on-device `SystemLanguageModel` only, with availability and language checks.
- Chat is device-only, private to the local caregiver identity, and never enters App Group storage, sync, family export, widgets, or a server model.
- One active conversation per `(identity, babyID)`; confirmed New Chat deletes that conversation only.
- Ask is read-only. Every query uses an explicit baby ID and current nondeleted records. Numeric and temporal facts come from Swift, not model prose.
- Keep existing Home, History, Insights, and Settings; put Ask between History and Insights.
- Use Conventional Commits. Add the actual number of new Swift package tests to `Makefile`'s `EXPECTED_TESTS` in the final gate commit.

## Review Focus

- A different caregiver account signs in on the same device: it must not see the previous account's chat (Task 1 test).
- New Chat is tapped during generation: a late answer must not recreate deleted messages (Task 4 test).
- A feed contains breast, pumped milk, and formula components: the handoff must preserve their order and types (Task 2 test).
- A log entry changes or is tombstoned after an answer: a new query uses current facts and an old source link reports missing content (Tasks 2 and 5 tests).
- Apple Intelligence is unavailable or returns a refusal/error: existing chat and unsent draft remain usable and no duplicate turn is saved (Tasks 3 and 4 tests).

**Interfaces:** `AskQuery` enumerates `.handoff`, `.latest(kind:)`, `.events(kind:window:)`, `.comparison(kind:window:)`, `.insights(range:)`, `.unsupported`, and `.needsClarification`; `AskFactBuilder.build(query:babyID:now:timeZone:) throws -> AskFacts` returns explicit window, fact IDs, typed values, and source IDs. Suggested handoff uses the preceding 24 hours. “Overnight” uses 18:00 yesterday to 06:00 today, ending at `now` if before 06:00; the answer names the dates chosen.
